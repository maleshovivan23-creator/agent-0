# AGENT-0 — ферма автономных воркеров

Проект про заработок без начальных вложений. Он честно разделяет два вопроса:

1. **Что вообще может приносить деньги без вложений** — и большинство популярных
   ответов («краны», «сибил-ферма кошельков», «airdrop-ферма», «bug bounty на
   полном автомате») не проходят проверку: либо платят $0.001–0.008 в час, либо
   запрещены правилами площадок, либо требуют вложений на газ.
2. **Что можно автоматизировать, не выходя за рамки правил** — разведку задач,
   проверку конкуренции, подготовку работы, бухгалтерию дохода.

Ферма делает второе и **осознанно отказывается** от первого. Каждый отказ
описан в коде и в дашборде: почему не работает, какой риск, чем заменить.

📄 **Что искать и где платят:** [docs/PLATFORMS.md](docs/PLATFORMS.md) — проверенные площадки, суммы, лимиты выплат по странам.
📄 **Как выжимать деньги:** [docs/PLAYBOOK.md](docs/PLAYBOOK.md) — ежедневный цикл, учёт часов, рычаги дохода.

## Команды можно писать по-русски

Внутри всё то же самое, английские имена продолжают работать (на них ссылаются
службы и cron), но запоминать их не нужно:

| По-русски | Что делает |
|---|---|
| `настройка` | заполнить `.env`: секреты вводятся скрыто, файл закрывается правами 600 |
| `контесты` | аудит-контесты: призовой пул, дедлайн, объём scope, EV/час |
| `досье <id>` | где править и что запускать: файлы-кандидаты и команды тестов |
| `слежение` | не отдали ли задачу, пока вы работаете (`--json`) |
| `дозор` | что сломалось, пока вас не было (`--json` для мониторинга) |
| `обучение` | что робот понял по вашим решениям: продуктивные запросы и типы работ |
| `проверка` | готовность: блокеры и как их снять (`--json` для скриптов) |
| `автопилот` | робот: поиск, проверка конкуренции, планы, черновики (`--once`, `--status`) |
| `потоки` | многозадачный режим: несколько заказов сразу (`--limit`, `--parallel`, `--plan`, `--status`) |
| `снапшот <канал>` | снять отчёт площадки в `snapshots/` там, где домен площадки открыт |
| `входящие` | что готово к публикации; `входящие show 3` — текст элемента |
| `входящие-отправлено <id>` / `входящие-пропустить <id>` | отметить сделанным или ненужным |
| `смена` | отчёт: что робот сделал за сутки |
| `направления` | три направления и распределение времени |
| `каналы-выплат --country DE` | как получить деньги в вашей стране |
| `кошелёк 0x…` (`--save`, `--json`) | проверить адрес для крипто-выплат и сохранить в `.env` |
| `площадка статус` · `площадка квесты` · `площадка лента` · `площадка отметиться` | AgentHansa: агент, квесты, лента, ежедневная отметка |
| `площадка кошелёк` · `площадка альянс red` | привязать адрес выплаты и выбрать альянс |
| `площадка отправить <id> --файл … --подтверждаю` | отправить работу на площадку (только человеком) |
| `настройка --show` | показать, что уже прописано (секреты маской) |
| `проверка-страны --country DE` | платёжный канал для заявки |
| `цикл --channel контесты` | разовый проход по воркерам |
| `дальше` | что брать в работу прямо сейчас |
| `конкуренция <id>` · `план <id>` · `заявка <id>` · `черновик <id>` | проверка, план, текст заявки, текст квеста |
| `часы --channel контесты --hours 2` · `выплата-запись` · `выплата-подтвердить <id>` | учет времени и денег |
| `бухгалтерия` · `аналитика` · `правила` · `отчёт` | состояние денег и политика |

Воркеров тоже можно называть по-русски: `гитхаб`, `контесты`, `площадки`, `разведка`.

## Чему робот учится сам

Ферма не угадывает, какие задачи стоит брать. Она запоминает три факта:

1. **сколько задач принёс каждый поисковый запрос** (наблюдение за проход);
2. **что вы сделали с готовым текстом** — отправили или пропустили (`входящие-отправлено` / `входящие-пропустить`);
3. **сколько денег реально подтверждено** (`выплата-подтвердить`).

Из этого считается вес запроса: продуктивные идут в начало очереди поиска, пустые
опускаются, но никогда не выбрасываются — рынок меняется. Посмотреть:

```bash
python -m agent.main обучение
```

Вес 1.0 — нейтрально (данных мало), меньше 1.0 — запрос приносил только мусор,
больше 1.0 — из него выходили отправленные заявки. Никаких случайных решений и
никаких «самообучающихся» выводов из воздуха: только статистика по фактам, и не
раньше, чем наберётся 3 наблюдения.

## Задача не только находится, но и доводится

Три вещи отделяют «нашёл задачу» от «получил деньги», и все три автоматизированы:

**1. Досье — где править.** Дорогой час уходит не на код, а на поиск места правки.
`досье <id>` читает дерево репозитория публичного API и выдаёт: файлы-кандидаты (с
приоритетом исходников над документацией), корень кода, сколько Solidity/Rust/TS-файлов,
команды запуска тестов из манифестов и список того, что приложить к PR. Для контестов
дополнительно разбирает `scope.txt`: сколько файлов в области проверки, что вне её и в
каком репозитории лежит сам код.

**2. Контесты с дедлайнами.** README контеста содержит призовой пул и даты — ферма их
читает. Если приём работ закрыт, контест больше не висит в очереди как «$23/час»:
такая задача помечается завершённой, а подготовленный план снимается с очереди.
Если времени меньше, чем нужно на саму работу, вероятность падает вчетверо, и это
написано прямо в оценке.

**3. Слежение за взятыми задачами.** Самая обидная потеря — две недели работы над
задачей, которую уже сделал кто-то другой. `слежение` сравнивает состояние задачи с
прошлой проверкой и сообщает изменение: появился открытый PR у соперника, выросли
число заявок, заказчик закрыл issue или бот платформы объявил о выплате. Итог — вердикт
и совет: добавить в свой PR то, чего нет у соперника, или переключиться на свежую задачу.

## Дозор: робот сообщает, что встал

Автономность полезна ровно до тех пор, пока кто-то замечает остановку. `дозор`
проверяет шесть вещей, каждая из которых означает потерю денег:

| Проверка | Что значит |
|---|---|
| Робот молчит дольше двух интервалов | процесс упал, машина уснула, кончился диск |
| Канал N проходов подряд без находок или с ошибками | сломался поиск, нужен новый запрос или ключ |
| Лимит GitHub исчерпан | следующий проход будет пустым без `GITHUB_TOKEN` |
| Готовые тексты ждут отправки дольше 12 часов | узкое место уже у человека, а не у робота |
| Отчёт площадки устарел или опустел | цикл в Actions встал: не тот секрет, сбой раннера |
| Код менялся после запуска автопилота | процесс держит старую версию в памяти и перезаписывает новые результаты |

Каналы, которые молчат по делу (нет ключа площадки, нет `data/scope.yaml`), в
проблемы не попадают — иначе к предупреждениям перестали бы относиться серьёзно.
Проблемы видны в `дозор`, в дашборде, в `/healthz` и приходят в Telegram, но не
чаще одного раза в 6 часов на одну и ту же проблему.

## Многозадачный режим: несколько заказов сразу

```bash
python -m agent.main потоки --plan          # что робот возьмёт и что оставит вам
python -m agent.main потоки                 # взять и сделать: 3 заказа параллельно
python -m agent.main потоки --limit 5 --parallel 4
python -m agent.main потоки --status        # сколько готового ждёт человека
```

Чем это отличается от обычного прохода:

- **Несколько задач параллельно.** Пул потоков ведёт до `MULTITASK_PARALLEL` заказов
  (по умолчанию 3); падение одной задачи не останавливает остальные — ошибка
  попадает в журнал, а не в лицо оператору.
- **Робот берёт только то, что доводит сам.** Для каждой задачи видно, кто её
  закрывает: робот (черновик ответа на квест, заявка и план работ, досье
  контеста) или человек (разведка по чужому scope — там нужна авторизация).
  Задача со сроками вне окна или закрытая не берётся вовсе.
- **Журнал заказа.** `reports/multitask-<дата>.md`: что взято, что получилось,
  сколько заняло, какой ровно командой это отправляется. Часы робота и часы
  человека в журнале считаются раздельно — складывать их значило бы завышать
  ставку $/час.
- **Граница не прячется.** Робот доводит работу до готового текста и
  доказательства; отправка на площадку, публикация заявки и выплаты остаются
  действиями человека: ключ площадки и ответственность за текст — его.
- **Работа для площадок тоже готовится.** У задачи с Taskmarket нет репозитория —
  там платят за результат на самой странице. Робот кладёт во «входящие» черновик
  работы: что прочитать в критериях приёмки, структуру ответа, объём, а также
  команды `часы` и `выплата-запись`, чтобы после отправки доход был учтён. Текст
  по-прежнему отправляет человек.

## Автономный режим: робот работает без вас

```bash
python -m agent.main autopilot            # робот: цикл, триаж, планы, черновики
python -m agent.main autopilot --once     # один проход
python -m agent.main autopilot --status   # состояние и интервал
python -m agent.main inbox                # что готово к публикации (ваше действие)
python -m agent.main shift --hours 24     # отчёт: что робот сделал за сутки
```

Робот сам решает, когда просыпаться: появилась свежая работа — возвращается к
минимальной паузе (по умолчанию 5 минут), рынок пуст — растягивает её до часа.
Всё, что он подготовил, попадает в очередь `inbox` с одним явным действием для
человека: «опубликовать заявку», «отправить текст квеста», «начать работу по плану».

| Робот делает сам | Человек делает |
|---|---|
| Ищет задачи в трёх направлениях, триажит, считает EV/час | Публикует заявку и отправляет квест (копия текста — `inbox show <id>`) |
| Пишет планы работ, черновики заявок и ответов на квесты | Делает работу |
| Ведёт очередь, heartbeat, отчёт смены, уведомления в Telegram | Подтверждает выплату `payout-verify` |

Стоп-кран: `touch data/STOP` (или `AUTOPILOT_ENABLED=false`). Живой мониторинг:
`curl localhost:8000/healthz` → `ok` / `degraded` / `stopped`. Развёртывание на
сервере, cron и в Docker — [docs/DEPLOY.md](docs/DEPLOY.md).

## Что нужно, чтобы начать зарабатывать

Сначала — заполнить настройки. Секреты вводятся скрыто (как пароль в терминале),
в истории команд и в переписке они не появляются, файл `.env` получает права 600 и
уже исключён из git:

```bash
python -m agent.main настройка            # спросит по очереди, Enter — пропустить
python -m agent.main настройка --show     # посмотреть, что уже задано (маской)
```

Затем — проверить, что ничего не мешает:

Одна команда отвечает на этот вопрос по вашей машине, а не в общем виде:

```bash
python -m agent.main doctor
```

Она проверяет 13 пунктов: файл `.env`, зависимости, базу, страну выплаты, рабочий
канал получения денег, адрес кошелька, токен GitHub и живую связь с API, ключ
площадки квестов, языковую модель, уведомления, авторизацию разведки, GitHub CLI.
Блокеры идут первыми, к каждому — команда или ссылка, которая его закрывает.
Код возврата 1, если работать ещё нельзя, поэтому проверку можно ставить в cron.

Минимум для старта — три пункта:

| Что | Зачем | Как |
|---|---|---|
| `GITHUB_TOKEN` | лимит поиска 5000 запросов/час вместо 60: свежие bounty забирают в первые часы | github.com/settings/tokens → токен без прав → `GITHUB_TOKEN=…` в `.env` |
| `ELIGIBILITY_COUNTRY` | без него ферма не знает, дойдут ли деньги, и не отправляет заявки | `ELIGIBILITY_COUNTRY=RU` (или ваш код страны) в `.env` |
| Канал получения денег | карта/Stripe работают не везде, а деньги нужны на руки | `python -m agent.main payout-rails --country RU` → завести первый вариант и привязать его на площадке |

Дальше — рабочий цикл:

```bash
python -m agent.main цикл         # собрать рынок по трём направлениям сразу
python -m agent.main дальше       # что делать прямо сейчас (только выше $3/час)
python -m agent.main конкуренция <id>  # проверить, не занята ли задача
python -m agent.main досье <id>   # где править и что запускать (файлы, команды)
python -m agent.main план <id>    # план работ от подагентов
python -m agent.main apply <id>   # текст заявки; публикация — вашими руками
python -m agent.main quest <id>   # черновик ответа на квест площадки (300–800 слов)
python -m agent.main hours-add agent_marketplaces 1.5
python -m agent.main payout-add agent_marketplaces 40 && python -m agent.main payout-verify <id>
```

Полный путь (в том числе что делает человек, а что ферма) печатает
`python -m agent.main doctor` в конце вывода и показывает дашборд в блоке
«Готовность: что мешает заработать».

## Площадки для агентов: их две, и обе без банка

| Площадка | Что это | Нужен ли ключ | Выплата |
|---|---|---|---|
| AgentHansa | квесты, red packets, форумные призы | да: `AGENTHANSA_API_KEY` (регистрация возвращает ключ) | USDC на Base, минимум 10 |
| Taskmarket (`taskmarket.dev`) | задачи в USDC: исследование, текст, код | нет — список задач открыт | USDC на Base в кошелёк |

Из песочницы домен Taskmarket закрыт, а с раннера GitHub — открыт. Поэтому у
обеих площадок один и тот же мост: workflow снимает отчёт в `snapshots/` и
коммитит его, а ферма читает файл локально — задачи попадают в очередь и в
дашборд с пометкой источника и возрастом отчёта. Вручную отчёт снимается командой
`снапшот taskmarket` (она же используется в CI как проверка доступа). Пустой
проход никогда не затирает прежний отчёт: иначе один сбой сети обнулил бы
вчерашние задачи, а свежая дата выдала бы их за новые.

Тот же мост работает и для AgentHansa: квесты из `snapshots/hansa-report.json`
попадают в очередь, даже когда домен площадки недоступен, — с пометкой источника,
возраста отчёта и советом открыть квест на площадке, если отчёту больше суток.

Taskmarket читается без ключа и без кабинета: канал разбирает открытую выдачу,
берёт награду, срок и число уже присланных работ и сам отсеивает толпу. Задача
«$2 USDC, 44 работы» в очередь не попадёт — это лотерея, а не работа; дорогая
задача с одной-двумя работами попадёт, потому что там ещё можно успеть первым.
Сроки и критерии приёмки всё равно подтверждает человек на странице задачи:
площадка не отдаёт их машиночитаемо.

## Три направления — работают параллельно

Ферма не ставит всё на один канал. Каждое направление закрывает свою задачу, и
цикл собирает данные по всем сразу (воркеры работают параллельно, поэтому цикл
длится столько же, сколько самый медленный из них).

| Направление | Воркер | Зачем именно оно | Потолок |
|---|---|---|---|
| **1. Быстрые деньги** | `github_bounties` | первая выплата быстрее всего, порог входа низкий | $50–$2,500 за задачу |
| **2. Потолок** | `audit_contests` | платят за качество находки, а не за скорость | медиана находки ~$2,000 |
| **3. Без банка** | `agent_marketplaces` | выплата в USDC не зависит от страны и Stripe | $10–$500 за квест |

Плюс отдельный воркер `bug_recon` (пассивная разведка строго по хостам из
`data/scope.yaml`) — он работает только при заполненном файле авторизации.

Посмотреть состояние направлений и распределение времени:

```bash
python -m agent.main directions
```

Ферма считает доли времени из измеренного EV/час по каждому каналу, но никогда
не обнуляет направление: канал без задач пока сохраняет небольшую долю, чтобы
не потерять его из вида. Текущий пример расчёта: контесты ~87% времени,
bounty ~6%, площадки для агентов ~8%.

## Как получить деньги (а не только заработать)

Заработать и получить — разные задачи. Stripe, через который платят Algora и
Opire, работает не во всех странах, а прямой вывод на карту российского банка
не работает вовсе. Проверка перед началом работы:

```bash
python -m agent.main payout-rails --country RU   # рабочие каналы + что не сработает
python -m agent.main eligibility --country RU    # та же проверка для заявки на задачу
python -m agent.main кошелёк 0x… --save          # проверить адрес и записать в .env
```

**Адрес кошелька проверяется до первой выплаты, а не после.** Крипто-перевод
необратим: ошибка в одном символе отправляет деньги чужому человеку, а площадка
при этом отчитается, что заплатила. Поэтому ферма проверяет адрес по правилам
сети: EVM (`0x…`) — контрольную сумму EIP-55 (опечатка в букве меняет регистр и
ловится), TRON (`T…`) — base58check, Solana — 32 байта. У адресов Solana
контрольной суммы нет, там опечатка даёт другой рабочий адрес: сверяйте символы
глазами. Кошелёк Phantom подходит: у него есть и EVM-адрес для Base (там платит
площадка агентов), и отдельный адрес Solana — для выплат в сети Solana нужен
второй, не первый. Seed-фразу ферма не спрашивает: ей нужен только публичный
адрес.

Каналы приёма и их ограничения разобраны в [docs/PLATFORMS.md](docs/PLATFORMS.md#65-как-получить-деньги-каналы-приёма-а-не-только-заработка):
USDC на кошелёк, USDT TRC-20, сервисы-посредники (Mellow, EasyStaff, Kleos, Ruul),
зарубежный счёт или карта, своя компания. Для каждого — что требуется, сколько
стоит и при каких условиях ломается.

### Площадка агентов AgentHansa: где живёт её цикл

Площадка платит в USDC на Base, то есть работает там, где карточные каналы нет.
Контракт ферма не угадывает: маршруты и поля вычитаны из официального клиента
площадки `agent-hansa-mcp` (npm) и её agent-руководства, а весь обмен идёт через
`agent/hansa.py`.

Что важно знать про среду: **из песочницы разработки домен площадки закрыт**
(разрешены только GitHub, PyPI и npm), а **раннер GitHub её видит** — это
проверяется шагом «Доступность площадки агентов» в CI. Поэтому цикл площадки
живёт в `.github/workflows/hansa.yml`:

1. Зарегистрировать агента (ключ показывается один раз, стоит $0.05 бонусом):
   ```bash
   curl -s -X POST https://www.agenthansa.com/api/agents/register \
     -H 'Content-Type: application/json' \
     -d '{"name":"agent-0","description":"Автономная ферма агента: аудит-контесты, bounty, планы и черновики"}'
   ```
2. GitHub → **Settings → Secrets and variables → Actions → New repository secret**:
   имя `AGENTHANSA_API_KEY`, значение — ключ из шага 1. В логи и в репозиторий он
   не попадает.
3. Actions → **AgentHansa** → *Run workflow*. Без секрета workflow не падает, а
   объясняет эти же шаги. Дальше он идёт по расписанию (каждые 3 часа): отметка,
   лента заданий, квесты — и складывает отчёт в `snapshots/hansa-report.json`,
   откуда его читает ферма.

Что делает робот и что человек: робот ищет квесты, считает EV/час, готовит текст
работы и доказательство; **отправку делает человек** — команда
`площадка отправить <id> --файл <текст> --подтверждаю` (без флага работа не
уходит: это проверено тестом). Кошелёк привязывается адресом из `PAYOUT_WALLET`
(`площадка кошелёк`) — с ним выплата приходит сразу, без него держится 3-7 дней.

**Отчёт работает и без сети.** Квесты из `snapshots/hansa-report.json` попадают
в очередь фермы как обычные возможности (`market:agenthansa:<id>`): с источником
`snapshot`, возрастом отчёта и предупреждением открыть квест на площадке, если
отчёту больше суток. В дашборде для них есть отдельная полка — сколько квестов,
лучшая награда, когда снят отчёт. Живой API всегда важнее отчёта: как только
ключ и сеть доступны, канал берёт данные оттуда.

**Условия задачи читает робот, а не человек.** Карточка в выдаче говорит «$199,
две работы, 29 дней» — по ней видно выгоду и не видно работы. Настоящие условия
живут на странице задачи, и её снимает раннер: `снапшот taskmarket --detail 5`
читает описание у пяти самых дорогих задач, кладёт в отчёт (`detail_found`), а
ферма добавляет его в черновик работой отдельной секцией «Что просит площадка».
Разбор идёт по нескольким стратегиям (мета-описание, JSON-LD, данные приложения)
— разметку площадки никто не обещал хранить неизменной, и если ни одна не
сработала, раннер пишет предупреждение, а не молчит.

**Настройки оператора переживают перезапуск среды.** Адрес кошелька — не секрет,
и терять его нельзя: без адреса выплата не уйдёт. Поэтому публичные настройки
(кошельки и страна) лежат в git — `data/operator.yaml`, — а `.env` и база нет.
Окружение и `.env` всегда сильнее файла: файл только заполняет то, чего нет.
Восстановление после перезапуска машины или новой песочницы — одна команда:

```bash
./scripts/restore.sh      # окружение, зависимости, .env по шаблону, проверка готовности
```

**Срок задачи не даёт ей умереть молча.** У задач площадок есть таймер, и после
него работу не примут, даже если она готова: `дальше` показывает «осталось 6 ч»
(красным, если меньше суток), а плитка дашборда — сколько задач закроется за
следующие сутки.

**Чего ферма не берёт, она говорит вслух.** Не всё выгодное выполнимо: конкурс
CUDA-ядер может давать $17/час на бумаге и требовать NVIDIA-карту, которой нет.
Такие задачи лежат в `data/veto.yaml` с причиной — файл в git, поэтому решение
переживает пересборку базы, а `дальше` показывает их отдельным списком рядом с
рекомендациями. Убрать строку достаточно, чтобы задача вернулась в очередь.

Досье и «дальше» тоже знают разницу: у квеста площадки нет репозитория GitHub, поэтому
робот не отправляет вас в `досье`/`план`, а показывает свой маршрут —
`площадка квест <id>` → `черновик <id>` → отправка человеком. У задачи Taskmarket
маршрут свой: открыть задачу и прочитать критерии приёмки → `черновик <id>` →
отправка человеком; если строки пришли из отчёта, вторым шагом стоит «сверьте
награду и срок на площадке». Автопилот для таких задач готовит во «входящие»
черновик работы, так что лучший заказ не остаётся без подготовленного текста.

### Почему это важнее, чем «просто список задач»

Реальный результат с живого рынка, обнаруженный триажем:

```
Low Handing Fruit Automation (SecureBananaLabs/bug-bounty #743), награда $700
  заявок /attempt: 36     открытых PR по задаче: 15     шанс успеха: ~0.1%
```

Без триажа ферма поставила бы эту задачу первой — и вы потеряли бы день.
С триажем она уходит в раздел «не тратить время», а наверх поднимаются
аудит-контесты с EV/час $22–23.

## Работает здесь и сейчас

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env

python -m agent.main status        # состояние фермы и деньги
python -m agent.main cycle         # сбор задач + проверка конкуренции
python -m agent.main next          # что делать прямо сейчас (по EV/час)
python -m agent.main plan <id>     # план работ: подагенты Scout/Analyst/Planner/Reviewer
python -m agent.main serve         # дашборд на 0.0.0.0:8000
pytest -q
```

## Как это приносит деньги

Ферма не платит вам деньги — она сокращает путь от «искать оплачиваемую работу»
до «сдать результат». Деньги приходят от заказчика:

1. `cycle` находит задачи и **проверяет, не занята ли каждая**: считает `/attempt`,
   открытые PR, подтверждает сумму из комментария бота платформы.
2. `next` сортирует оставшееся по ожидаемой ценности часа и показывает, что
   делать; всё, что ниже планки `MIN_EV_PER_HOUR`, честно помечается как
   «не тратить время».
3. `plan <id>` собирает рабочий план по плейбуку (тесты, документация, баг,
   фича, аудит) с критериями готовности и типовыми причинами отказа.
4. `apply <id> --country DE` готовит текст заявки **и проверяет, дойдёт ли до вас
   выплата**: Stripe не обслуживает часть стран, и об этом лучше узнать до работы.
5. Вы делаете работу и публикуете PR сами. Публикация от вашего имени —
   возможность `submit_deliverable_human_approved`: разрешена, но требует человека.
6. Доход учитывается с доказательством и **отдельным подтверждением**:

```bash
python -m agent.main hours-add --channel github_bounties --hours 2.5
python -m agent.main payout-add --channel github_bounties --amount 150 \
    --evidence "PR #123 merged, выплата 2026-09-20"
python -m agent.main payout-verify 1
python -m agent.main analytics      # эффективная ставка $/час
```

Заявленная сумма и подтверждённый доход считаются раздельно. Агент не может сам
превратить своё «я заработал» в доход — иначе в базе быстро появятся красивые
цифры без денег.

## Как увеличить доход (рычаги, а не обещания)

| Рычаг | Что делает ферма | Ожидаемый эффект |
|---|---|---|
| Проверка конкуренции | `triage`: `/attempt`, открытые PR, статус оплаты | Убирает работу с шансом ~0.1% — главный источник потерянных дней |
| Свежесть | фильтр `created:>` + бонус к оценке | Bounty выигрывают в первые 1–3 дня, пока поле пустое |
| Плейбуки | готовые шаги и чек-листы по типам задач | Сокращает часы на повторяемых задачах |
| Потолок | канал `audit_contests` | EV/час $20–45 против $0–3 на GitHub-bounty |
| Проверка выплат | `eligibility` до начала работы | Не даёт сдать работу в страну, куда платёж не дойдёт |
| Измерение | `analytics`: доход ÷ залогированные часы | Показывает, какие типы задач кормят, а какие нет |

Подробнее с цифрами и источниками: [docs/PLAYBOOK.md](docs/PLAYBOOK.md).

## Честные ожидания

- Первые деньги приходят не за день: цикл — найти свежую задачу, сделать PR,
  дождаться ревью и выплаты. Многие PR не мержат, и это нормальная часть работы.
- GitHub-bounty перегружены: триаж в среднем отсеивает большинство найденных
  задач. Это не баг фермы, а свойство рынка.
- Аудит-контесты дают в разы больше, но требуют Solidity/Rust и времени на
  обучение. Наивный «полный автомат» там невозможен: ферма готовит площадь
  работ, находку делает человек.
- «Пассивного» дохода без вложений не существует. Существует доход за работу,
  в которой автоматизирована разведка, проверка и рутина.

## Про bug bounty

Полностью автономный bug bounty-агент — это либо выход за scope, либо
автоматизация того, что и так безопасно. Поэтому:

- **автоматизировано:** инвентаризация, DNS/TLS/HTTP-отпечатки, сбор контекста,
  черновик отчёта;
- **оставлено человеку:** проверка гипотез, эксплуатация, подача отчёта;
- **жёсткое ограничение:** без `data/scope.yaml` с программой и хостами воркер
  не запускается. Хост не из файла — отказ и запись в журнал отказов.

```bash
cp data/scope.example.yaml data/scope.yaml   # заполнить только тем, на что есть разрешение
```

## Архитектура

```
agent/
  policy.py        — реестр разрешённых и запрещённых возможностей (fail-closed)
  scoring.py       — награда, трудозатраты, свежесть, EV/час, отсев приманок
  triage.py        — проверка конкуренции: /attempt, открытые PR, статус оплаты
  playbooks.py     — шаги и чек-листы по типам задач (снижают часы)
  subagents.py     — Scout → Analyst → Planner → Reviewer + текст PR
  eligibility.py   — куда дойдёт выплата, и чем заменить заблокированный канал
  llm.py           — Anthropic / Ollama / детерминированный фолбэк
  ledger.py        — SQLite: возможности, часы, выплаты (заявка ≠ доход), аналитика
  farm.py          — оркестратор, фильтр по EV, список «не тратить время»
  channels/        — воркеры, каждый объявляет одну capability
  dashboard.py     — панель без внешних зависимостей
  main.py          — CLI
docs/
  PLATFORMS.md     — где платят: площадки, суммы, лимиты по странам
  PLAYBOOK.md      — как выжимать деньги: цикл, учёт часов, рычаги
```

Ключевое правило: воркер объявляет одну capability, `farm.py` спрашивает
`policy.py` до любого сетевого вызова, а всё, что не описано в реестре,
считается запрещённым.

## Безопасность

- приватные ключи и seed-фразы не нужны и не принимаются: ферма не двигает
  средства и не имеет доступа к кошельку;
- `GITHUB_TOKEN` нужен только read-only для публичного поиска;
- воркер разведки по умолчанию пассивный, с паузой между запросами;
- эксплуатации уязвимостей в коде нет;
- `ANTHROPIC_API_KEY` читается только из окружения и никуда не логируется.
